# 源码分析与证据

## 模块地图

确认项目边界、入口和配置来源，再按职责划分模块。目录不必然等于模块。记录每个模块的关键文件/符号、调用者、依赖、输入输出、分析状态和报告锚点。区分已启用、未启用和可选路径。用户指定逐文件时增加附录。

## 追踪顺序

1. 入口接收什么：CLI 参数、HTTP 请求、文件、配置、张量或事件。
2. 初始化何时发生：配置覆盖、模型、连接、缓存和随机种子。
3. 每次变换前后是什么：类型、结构、维度、单位、语义与状态。
4. 条件由谁判断：精确谓词、边界、优先顺序和短路行为。
5. 出口产生什么：正常值、错误对象、异常、文件、数据库写入或外部动作。
6. 回路怎样结束：迭代、早停、重试次数、耗尽出口；未知则明确写未知。
7. 并发怎样汇合：分派、等待、共享状态、超时与部分失败。

流程图建立在事实之上，不从理想架构反推实现。

## 步骤 ID

每步使用稳定 ID，如 S01。记录目的、模块、输入、内部处理、输出、副作用、分支、例子和源码。边记录条件及数据。子流程使用 S04.1 等编号，或独立 ID 加父步骤链接。

## 证据强度

- 源码确认：读实现和调用上下文，支持静态行为。
- 运行确认：有命令、输入、环境和输出，说明实测范围。
- 分析推断：解释或设计理由未经作者证实，写清条件。
- 未核实：不可读、依赖缺失、动态代码或环境不足。

记录提交和工作区状态，行号实际核对。可内嵌带行号代码，保证离线依据可读。测试存在不代表已通过，函数存在不代表当前路径会执行。

## 例子选择

覆盖主成功路径、主要路由、拒绝/异常出口、重试或早停（存在时）。每条路径保留可追踪的字段。同一输入满足多个条件时，展示优先级及源码依据。静态推演与实测分开；有限例子不代表穷尽测试或形式证明。

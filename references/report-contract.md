# 报告内容契约

## 阅读顺序

项目目标与范围 → 技术背景 → 完整流程 → 贯穿样例 → 模块和步骤 → 验证与覆盖 → 论文对照（适用时）→ 源码与引用。大小项目均不得省略完整流程和逐步例子。

## 流程图

包含真实入口、重要行为节点、决策、异常、提前返回、循环和终点。每条边标数据或条件；判断写精确谓词，不能只有“分支 A”。聚合节点链接完整子流程。区分控制、数据和异步含义；颜色不是唯一语义。图中步骤可跳详情。回边写停止条件，并行写汇合条件。

## 每个步骤卡片

| 字段 | 必须回答 |
|---|---|
| 目的与位置 | 为什么存在、谁调用、接下来去哪 |
| 输入 | 类型、结构、字段、维度/单位和约束 |
| 内部处理 | 真实调用、计算、参数和执行优先级 |
| 输出 | 返回值、状态、副作用；无返回值需直说 |
| 分支与边界 | 判断、失败、早退和上游前提 |
| 示例 | 本步前后具体值，关联贯穿样例 |
| 证据 | 文件、符号、核对行号和证据状态 |

辅助判断/汇合节点可复用相邻契约，但说明它只是图上的控制点，并指向实际源码。

## 技术背景

说明待解决的问题、最小原理、本项目实际调用、配置和限制。区分运行时、开发工具和未启用组件。作者未说的设计理由标分析推断。版本敏感知识查官方文档并保留引用。

## 例子

每例有输入、选择理由、结果、节点 ID 路径、分支原因、各步输入输出。未经过的节点写“本例未经过”，不借用其他案例数据。可在图上高亮路径，但无 JS 也要读到路径和数据。

## 验证与覆盖

列全范围内模块、源码、说明位置和状态。记录环境、命令、执行结果、未运行内容和原因。对外部系统与缺少例子的路径明确说明。观测若干例子通过不代表项目全部正确。

## 离线与排版

单文件含 CSS、必要 JS、图与数据，使用系统字体和内联 SVG。代码、JSON、文件名按文本转义。目录、步骤 ID、图文导航、表格滚动与打印有效；核心内容静态可读。数值图需要真实来源、单位与条件，不能制造装饰性指标。
